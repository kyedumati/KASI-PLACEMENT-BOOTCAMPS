## How every session runs { .ksr-section-title }

<div class="ksr-steps" markdown>
<div markdown>**Start with the interview**

Five minutes on a real interview question that the session answers.</div>
<div markdown>**See it typed live**

The concept and its code template, written in front of the class.</div>
<div markdown>**Solve it yourself**

Thirty minutes of lab: one problem demonstrated, one guided, one solo.</div>
<div markdown>**Debrief and commit**

Complexity, common mistakes, then a commit to the student's GitHub repository.</div>
</div>

## What students leave with { .ksr-section-title }

<div class="grid cards" markdown>

-   :material-github:{ .lg } **A public record of work**

    ---

    One GitHub repository with a commit for every lab and every evening practice set.

-   :material-shape-outline:{ .lg } **Patterns, not answers**

    ---

    The ability to read a new problem and name the pattern it needs, with a template for each.

-   :material-account-voice:{ .lg } **Interview language**

    ---

    Practice at explaining complexity and design choices aloud, from the questions that close every session.
